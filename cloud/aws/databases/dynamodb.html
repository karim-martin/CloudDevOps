Amazon DynamoDB

AWS

Serverless NoSQL database with single-digit millisecond performance at any scale.

When Do You Use DynamoDB Instead of SQL?

Use DynamoDB when you need: (1) massive scale — millions of reads/writes per second, (2) simple access patterns — always look up by user ID, order ID, etc., (3) zero ops — serverless, no cluster to manage. Avoid DynamoDB for complex SQL queries, JOINs, or ad-hoc analytics. If you're unsure, start with RDS.

Basic Operations

import boto3
from boto3.dynamodb.conditions import Key

dynamodb = boto3.resource('dynamodb')
table = dynamodb.Table('Users')

# Create item
table.put_item(Item={
    'userId': 'user-123',
    'email': 'alice@example.com',
    'createdAt': '2024-01-15T10:00:00Z',
    'plan': 'pro'
})

# Get item by primary key (fast!)
response = table.get_item(Key={'userId': 'user-123'})
user = response['Item']

# Query all items with same partition key
response = table.query(
    KeyConditionExpression=Key('userId').eq('user-123')
)

Capacity Modes

⚡

On-Demand

Pay per request. No capacity planning. Great for unpredictable or spiky traffic. More expensive at steady-state load.

📊

Provisioned + Auto Scaling

Set read/write capacity units. Use Auto Scaling to adjust. Up to 70% cheaper than on-demand for predictable traffic.
