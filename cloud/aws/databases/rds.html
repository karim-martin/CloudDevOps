Amazon RDS

AWS

Managed relational databases — MySQL, PostgreSQL, SQL Server, and more.

RDS = A Database You Never Have to Maintain

RDS (Relational Database Service) runs MySQL, PostgreSQL, MariaDB, Oracle, or SQL Server for you. AWS handles automated backups (daily + continuous transaction logs), software patches, Multi-AZ failover, and read replicas. You connect to it exactly like a self-hosted database — it's just the servers that AWS manages.

Key Features

🔄

Multi-AZ Deployment

RDS maintains a synchronous standby replica in a different AZ. If the primary fails, failover happens automatically in ~60 seconds with no data loss.

📖

Read Replicas

Offload read-heavy traffic to up to 5 asynchronous read replicas. Promote a replica to primary instantly if needed.

💾

Automated Backups

Daily snapshots + continuous transaction log backups. Restore to any point in the last 35 days in minutes.

📈

Storage Auto Scaling

Enable storage autoscaling and RDS grows disk automatically when usage exceeds your threshold — no manual resize.

Create RDS (PostgreSQL) with AWS CLI

aws rds create-db-instance \
  --db-instance-identifier myapp-db \
  --db-instance-class db.t3.medium \
  --engine postgres \
  --engine-version 15.4 \
  --master-username admin \
  --master-user-password MySecretPassword123 \
  --allocated-storage 20 \
  --vpc-security-group-ids sg-0123456789 \
  --db-subnet-group-name my-db-subnet-group \
  --multi-az \
  --no-publicly-accessible \
  --backup-retention-period 7

Connect from EKS Pod

# Store credentials in Secrets Manager (never hardcode!)
aws secretsmanager create-secret \
  --name myapp/database \
  --secret-string '{"host":"myapp-db.cluster.us-east-1.rds.amazonaws.com","port":5432,"username":"app","password":"secret"}'

# In your app, retrieve the secret at startup:
# python example
import boto3, json
client = boto3.client('secretsmanager')
secret = json.loads(client.get_secret_value(SecretId='myapp/database')['SecretString'])
Security Best Practice

Always deploy RDS in a private subnet with no public IP. Access it only from within the VPC. Use Security Groups to allow only your EKS node security group to connect on port 5432/3306.
