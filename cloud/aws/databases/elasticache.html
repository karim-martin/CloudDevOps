Amazon ElastiCache

AWS

Managed in-memory caching with Redis and Memcached.

Caching = Serving Answers Without Asking the Database

Imagine your app fetches the same user profile from the database 1,000 times per second. Each database query takes 5–20ms. With caching, the first request fetches from the database and stores the result in Redis (in-memory, ~0.1ms reads). The next 999 requests read from Redis — 100× faster. ElastiCache is a managed Redis or Memcached cluster.

Redis vs Memcached

FeatureRedisMemcached
Data StructuresStrings, Lists, Sets, Hashes, Sorted SetsStrings only
PersistenceOptional (RDB/AOF)None
ReplicationYes (primary + replicas)No
Cluster ModeYes (Redis Cluster)Yes
Use CaseCache + sessions + leaderboards + queuesSimple cache only
Choose WhenAlmost alwaysNeed multi-threaded cache only

Common Caching Patterns

import redis
import json

r = redis.Redis(host='mycluster.abc123.0001.use1.cache.amazonaws.com', port=6379)

def get_user(user_id: str):
    # Try cache first
    cached = r.get(f'user:{user_id}')
    if cached:
        return json.loads(cached)  # Cache hit!
    
    # Cache miss — fetch from database
    user = db.query("SELECT * FROM users WHERE id = %s", user_id)
    
    # Store in cache for 5 minutes (TTL = 300s)
    r.setex(f'user:{user_id}', 300, json.dumps(user))
    return user
Session Storage

ElastiCache Redis is the standard way to store HTTP sessions in distributed apps. Instead of sticky sessions (routing users to the same server), all servers read/write to Redis — any pod can serve any request.
