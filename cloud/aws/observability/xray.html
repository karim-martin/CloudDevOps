AWS X-Ray

AWS

Distributed tracing — understand how requests flow through your services.

X-Ray Shows You the Life of a Request

In a microservices app, a single user request might touch 5–10 services. If something is slow, which service is the bottleneck? X-Ray instruments your code to track each step a request takes, measuring the time spent in each service. It shows a service map and a trace waterfall — like browser DevTools Network tab, but for your backend services.

X-Ray SDK Integration

# Python (Flask app)
from aws_xray_sdk.core import xray_recorder
from aws_xray_sdk.ext.flask.middleware import XRayMiddleware

app = Flask(__name__)
xray_recorder.configure(service='my-api')
XRayMiddleware(app, xray_recorder)

@app.route('/users/<id>')
def get_user(id):
    # Automatically traced — X-Ray records this segment
    with xray_recorder.in_subsegment('database'):
        user = db.get_user(id)
    return jsonify(user)
// .NET 8 (Program.cs)
builder.Services.AddAWSService<Amazon.XRay.Recorder.Handlers.AwsSdk.AWSSDKHandler>();
builder.Services.AddXRayForAspNet(o => o.ServiceName = "my-api");

app.UseXRay("my-api");

Trace Analysis

Once instrumented, X-Ray shows:

  • Service Map — visual graph of all services and their connections
  • Trace List — individual requests with their full call tree
  • Latency Distribution — histogram of response times
  • Error Analysis — which services have the most errors and faults
OpenTelemetry Alternative

AWS supports OpenTelemetry (vendor-neutral tracing standard) via the AWS Distro for OpenTelemetry (ADOT). This lets you send traces to X-Ray, Jaeger, or any backend — useful if you want to avoid vendor lock-in.
