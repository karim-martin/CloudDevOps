AWS Compute

AWS

Run containers, functions, and virtual machines on AWS.

Compute = Where Your Code Runs

Compute services are the "engines" of the cloud — they actually run your application code. AWS offers several options: EC2 (rent a virtual machine), EKS (run containers in Kubernetes), Fargate (run containers without managing machines), and Lambda (run a function in response to an event). Most modern apps use EKS or Fargate.

AWS Compute Options — When to Use What
🖥️ EC2
Full control. Virtual machine. You manage OS patches.
⚙️ EKS
Kubernetes clusters. Best for microservices at scale.
📦 Fargate
Serverless containers. No nodes to manage.
⚡ Lambda
Functions. Run code on events. Scales to zero.

EKS

Elastic Kubernetes Service. Managed Kubernetes clusters — AWS manages the control plane, you manage worker nodes (or use Fargate for serverless nodes).

Fargate & Lambda

Serverless compute. Fargate runs containers without managing EC2 instances. Lambda runs individual functions triggered by events (HTTP, queues, schedules).

Key Concepts

🌍

Regions & AZs

Deploy to multiple Availability Zones within a Region for fault tolerance. EKS distributes nodes across AZs automatically.

📏

Auto Scaling

EKS uses Cluster Autoscaler to add/remove nodes. Kubernetes HPA scales pods. Fargate scales containers automatically.

💰

Cost Optimization

Use Spot Instances for non-critical workloads (up to 90% savings). Fargate charges per CPU/memory second — no idle cost.

🔒

Security Groups

Every EC2 instance and EKS node has a Security Group — a stateful firewall controlling inbound/outbound traffic.
