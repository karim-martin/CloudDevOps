Amazon EKS

AWS

Elastic Kubernetes Service — managed Kubernetes on AWS.

What is EKS?

EKS (Elastic Kubernetes Service) lets you run Kubernetes on AWS without installing or managing the Kubernetes control plane yourself. Think of Kubernetes as an "operating system for containers" — it decides which machine runs which container, restarts crashed containers, and balances traffic. EKS means AWS manages the control plane (the brain), and you just deploy your apps.

Key Concepts

Node Groups

A Node Group is a set of EC2 instances that act as Kubernetes worker nodes. You define the instance type (e.g., t3.medium), min/max count, and AWS manages launching and registering them with EKS.

Managed vs Self-Managed Nodes

Use Managed Node Groups — AWS handles node updates, draining, and replacement. Self-managed nodes give more control but require more ops work.

Fargate Profiles

Instead of EC2 nodes, EKS can run pods on AWS Fargate — fully serverless. No nodes to manage, patch, or scale. Fargate is ideal for bursty workloads and CI/CD jobs.

IRSA — IAM Roles for Service Accounts

This is how EKS pods authenticate to AWS services (S3, RDS, Secrets Manager) without any credentials. Each pod gets a Kubernetes Service Account linked to an IAM Role. AWS verifies the pod's identity via OIDC and grants the IAM permissions.

# Annotate a Service Account to use an IAM role
kubectl annotate serviceaccount my-app \
  eks.amazonaws.com/role-arn=arn:aws:iam::123456789:role/MyAppRole

Create an EKS Cluster

# Using eksctl (recommended CLI for EKS)
eksctl create cluster \
  --name my-cluster \
  --region us-east-1 \
  --nodegroup-name workers \
  --node-type t3.medium \
  --nodes 2 \
  --nodes-min 1 \
  --nodes-max 4 \
  --managed
# Configure kubectl to use the new cluster
aws eks update-kubeconfig \
  --region us-east-1 \
  --name my-cluster

# Verify nodes are ready
kubectl get nodes

Deploy an Application

# deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
spec:
  replicas: 3
  selector:
    matchLabels:
      app: my-app
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
      - name: app
        image: 123456789.dkr.ecr.us-east-1.amazonaws.com/my-app:latest
        ports:
        - containerPort: 8080
        resources:
          requests:
            memory: "128Mi"
            cpu: "250m"
          limits:
            memory: "256Mi"
            cpu: "500m"
