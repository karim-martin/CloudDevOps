Fargate & Lambda

AWS

Serverless compute — run containers and functions without managing servers.

Serverless = No Servers to Manage

Fargate runs your Docker containers without you needing to provision or manage EC2 instances. Lambda runs a function (a piece of code) in response to an event — an HTTP request, a file upload, a scheduled timer — and you pay only for the milliseconds it runs. Both scale automatically from zero to thousands of concurrent executions.

AWS Fargate

Fargate is a serverless compute engine for containers. Use it with ECS (Elastic Container Service) or EKS. No nodes, no patching, no capacity planning.

# EKS Fargate Profile — run matching pods serverlessly
aws eks create-fargate-profile \
  --cluster-name my-cluster \
  --fargate-profile-name fp-default \
  --pod-execution-role-arn arn:aws:iam::123:role/FargatePodRole \
  --selectors namespace=production

AWS Lambda

Lambda runs code in response to events. Common triggers: API Gateway (HTTP), S3 (file uploads), SQS (messages), EventBridge (scheduled), DynamoDB streams.

# Simple Lambda function (Python)
import json

def handler(event, context):
    name = event.get('name', 'World')
    return {
        'statusCode': 200,
        'body': json.dumps({'message': f'Hello, {name}!'})
    }
# Deploy with AWS CLI
aws lambda create-function \
  --function-name hello-world \
  --runtime python3.12 \
  --role arn:aws:iam::123:role/lambda-role \
  --handler lambda_function.handler \
  --zip-file fileb://function.zip
