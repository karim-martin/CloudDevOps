Amazon ECR

AWS

Elastic Container Registry — private Docker image storage for AWS.

ECR = A Private Hub for Your Docker Images

When you build a Docker image, you need somewhere to store it so Kubernetes can pull it when deploying. ECR is AWS's private container registry — like Docker Hub, but private and integrated with your AWS account. Your EKS cluster, Fargate tasks, and CodeBuild jobs all authenticate to ECR automatically using IAM.

Push an Image to ECR

# 1. Create a repository
aws ecr create-repository \
  --repository-name my-app \
  --region us-east-1

# 2. Authenticate Docker to ECR
aws ecr get-login-password --region us-east-1 | \
  docker login --username AWS --password-stdin \
  123456789.dkr.ecr.us-east-1.amazonaws.com

# 3. Build your image
docker build -t my-app:v1.0.0 .

# 4. Tag for ECR
docker tag my-app:v1.0.0 \
  123456789.dkr.ecr.us-east-1.amazonaws.com/my-app:v1.0.0

# 5. Push
docker push 123456789.dkr.ecr.us-east-1.amazonaws.com/my-app:v1.0.0

Use ECR Image in Kubernetes

apiVersion: apps/v1
kind: Deployment
spec:
  template:
    spec:
      containers:
      - name: my-app
        image: 123456789.dkr.ecr.us-east-1.amazonaws.com/my-app:v1.0.0
        # EKS nodes/Fargate automatically authenticate via IAM — no imagePullSecrets needed!

ECR Features

🔍

Image Scanning

ECR scans images for CVEs (known vulnerabilities) using Amazon Inspector. Block deployments of images with critical vulnerabilities.

📜

Lifecycle Policies

Automatically delete old image tags to save storage costs. Keep the last 10 tags per repository, delete older ones.

🔒

Immutable Tags

Prevent image tags from being overwritten. Enforce that :v1.0.0 always refers to the same exact image.

🌍

Replication

Replicate images across regions for multi-region deployments. Reduces pull latency and adds disaster recovery.
