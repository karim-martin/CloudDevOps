ALB & NLB

AWS

Application and Network Load Balancers — route traffic to your EKS workloads.

A Load Balancer is a Traffic Director

Imagine 3 copies of your app running. Which one handles each incoming request? The Load Balancer decides. It also: terminates SSL (handles HTTPS encryption), checks if pods are healthy before sending traffic, and routes different URL paths to different services (/api → backend, / → frontend). In EKS, ALB is typically managed by the AWS Load Balancer Controller — it automatically creates ALBs from Kubernetes Ingress resources.

ALB vs NLB

FeatureALB (Application)NLB (Network)
LayerLayer 7 (HTTP/HTTPS)Layer 4 (TCP/UDP/TLS)
RoutingPath, host, header, queryPort only
SSL TerminationYesYes (TLS passthrough also available)
WebSocketsYesYes
Latency~1ms addedUltra-low, static IP
Use With EKSIngress (HTTP services)TCP services, gRPC, gaming

ALB Ingress in EKS

# Install AWS Load Balancer Controller first (via Helm)
helm repo add eks https://aws.github.io/eks-charts
helm install aws-load-balancer-controller eks/aws-load-balancer-controller \
  -n kube-system \
  --set clusterName=my-cluster \
  --set serviceAccountAnnotations."eks\.amazonaws\.com/role-arn"=arn:aws:iam::123:role/LBControllerRole
# ingress.yaml — ALB created automatically
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: my-app-ingress
  annotations:
    kubernetes.io/ingress.class: alb
    alb.ingress.kubernetes.io/scheme: internet-facing
    alb.ingress.kubernetes.io/target-type: ip
    alb.ingress.kubernetes.io/certificate-arn: arn:aws:acm:us-east-1:123:certificate/abc
    alb.ingress.kubernetes.io/listen-ports: '[{"HTTP":80},{"HTTPS":443}]'
    alb.ingress.kubernetes.io/ssl-redirect: '443'
spec:
  rules:
  - host: myapp.example.com
    http:
      paths:
      - path: /api
        pathType: Prefix
        backend:
          service: {name: backend-svc, port: {number: 8080}}
      - path: /
        pathType: Prefix
        backend:
          service: {name: frontend-svc, port: {number: 80}}
