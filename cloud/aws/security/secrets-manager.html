AWS Secrets Manager

AWS

Securely store, retrieve, and rotate credentials and API keys.

Never Put Passwords in Your Code

One of the most common security vulnerabilities is hardcoded credentials — database passwords or API keys committed to a Git repository. AWS Secrets Manager stores these securely and gives your application a way to retrieve them at runtime via API. Your code never sees the credential directly — it asks Secrets Manager, and Secrets Manager returns it if the code has IAM permission.

Store and Retrieve a Secret

# Store a database password
aws secretsmanager create-secret \
  --name myapp/prod/database \
  --description "Production DB credentials" \
  --secret-string '{
    "username": "app_user",
    "password": "S3cur3P@ss!",
    "host": "mydb.cluster.us-east-1.rds.amazonaws.com",
    "port": 5432,
    "dbname": "myapp"
  }'
# Retrieve in Python (using IRSA — no credentials needed)
import boto3, json

def get_db_config():
    client = boto3.client('secretsmanager', region_name='us-east-1')
    response = client.get_secret_value(SecretId='myapp/prod/database')
    return json.loads(response['SecretString'])
# Retrieve in .NET
var client = new AmazonSecretsManagerClient(RegionEndpoint.USEast1);
var response = await client.GetSecretValueAsync(new GetSecretValueRequest {
    SecretId = "myapp/prod/database"
});
var config = JsonSerializer.Deserialize<DbConfig>(response.SecretString);

Automatic Secret Rotation

Secrets Manager can automatically rotate RDS, Redshift, and DocumentDB credentials on a schedule using a Lambda function. The old password stays valid for a grace period while your app picks up the new one.

aws secretsmanager rotate-secret \
  --secret-id myapp/prod/database \
  --rotation-lambda-arn arn:aws:lambda:us-east-1:123:function:SecretsManagerRotation \
  --rotation-rules AutomaticallyAfterDays=30
