Azure Container Apps

Azure

Serverless containers — run microservices and event-driven workloads without managing Kubernetes.

Container Apps = Kubernetes Without the Kubernetes

Azure Container Apps runs on Kubernetes under the hood, but you never interact with K8s directly. You just say 'run this container, scale it based on HTTP traffic or queue depth.' It uses KEDA (Kubernetes Event-Driven Autoscaling) to scale from 0 to 1000 instances based on any event source — HTTP requests, Azure Service Bus messages, cron schedules, or custom metrics.

Deploy a Container App

# Create environment
az containerapp env create \
  --name myapp-env \
  --resource-group myapp-rg \
  --location eastus

# Deploy a container
az containerapp create \
  --name myapi \
  --resource-group myapp-rg \
  --environment myapp-env \
  --image myappcr.azurecr.io/api:v1.0 \
  --target-port 8080 \
  --ingress external \
  --registry-server myappcr.azurecr.io \
  --min-replicas 0 \
  --max-replicas 10 \
  --scale-rule-name http-rule \
  --scale-rule-type http \
  --scale-rule-http-concurrency 100

KEDA Scaling Rules

# containerapp.yaml — scale on Azure Service Bus queue depth
properties:
  configuration:
    ingress:
      targetPort: 8080
      external: true
  template:
    scale:
      minReplicas: 0
      maxReplicas: 20
      rules:
      - name: queue-based-scaling
        custom:
          type: azure-servicebus
          metadata:
            queueName: job-queue
            messageCount: "5"  # 1 replica per 5 messages
          auth:
          - secretRef: servicebus-connection
            triggerParameter: connection
