Azure AKS

Azure

Azure Kubernetes Service — managed Kubernetes with enterprise integrations.

AKS = Kubernetes, Managed by Microsoft

AKS handles the Kubernetes control plane (the brain) — you just create a cluster and deploy your apps. AKS integrates deeply with Azure services: Entra ID for authentication, Key Vault for secrets (mounted as files in pods), Azure Monitor for observability, and Azure Container Registry for images. It also supports Workload Identity — pods get Azure permissions without any credentials.

Create AKS Cluster

# Create resource group
az group create --name myapp-rg --location eastus

# Create AKS cluster with Workload Identity enabled
az aks create \
  --resource-group myapp-rg \
  --name myapp-cluster \
  --node-count 3 \
  --node-vm-size Standard_D2s_v3 \
  --enable-oidc-issuer \
  --enable-workload-identity \
  --enable-addons monitoring \
  --attach-acr myappcr \
  --network-plugin azure \
  --generate-ssh-keys

# Get credentials for kubectl
az aks get-credentials --resource-group myapp-rg --name myapp-cluster

Workload Identity (keyless auth to Azure)

# Create managed identity
az identity create --name myapp-identity --resource-group myapp-rg

# Get OIDC issuer URL
OIDC_URL=$(az aks show --resource-group myapp-rg --name myapp-cluster \
  --query "oidcIssuerProfile.issuerUrl" -o tsv)

# Create federated credential linking K8s ServiceAccount to managed identity
az identity federated-credential create \
  --name myapp-fedcred \
  --identity-name myapp-identity \
  --resource-group myapp-rg \
  --issuer "$OIDC_URL" \
  --subject "system:serviceaccount:production:myapp-sa"

# Now annotate the Kubernetes ServiceAccount
kubectl annotate serviceaccount myapp-sa \
  azure.workload.identity/client-id=$(az identity show --name myapp-identity -g myapp-rg --query clientId -o tsv)
