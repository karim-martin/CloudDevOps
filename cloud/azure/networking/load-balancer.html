Azure Load Balancer & Application Gateway

Azure

Distribute traffic to your AKS workloads with SSL termination and WAF.

Two Load Balancers for Two Different Jobs

Azure Load Balancer operates at Layer 4 (TCP/UDP) — it just forwards packets without looking at HTTP content. It's simple, fast, and ultra-low latency. Application Gateway operates at Layer 7 (HTTP/HTTPS) — it can inspect URLs, headers, and cookies, do SSL termination, WAF protection, and route /api traffic to your backend and / to your frontend. For AKS Ingress, use Application Gateway via the AGIC add-on.

AGIC — Application Gateway Ingress Controller

# Enable AGIC when creating AKS
az aks create \
  --name myapp-cluster \
  --resource-group myapp-rg \
  --enable-addons ingress-appgw \
  --appgw-name myapp-gateway \
  --appgw-subnet-cidr 10.1.0.0/16
# ingress.yaml — Application Gateway routes automatically created
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: myapp-ingress
  annotations:
    kubernetes.io/ingress.class: azure/application-gateway
    appgw.ingress.kubernetes.io/ssl-redirect: "true"
spec:
  tls:
  - hosts: [myapp.example.com]
    secretName: myapp-tls
  rules:
  - host: myapp.example.com
    http:
      paths:
      - path: /api
        pathType: Prefix
        backend:
          service: {name: backend-svc, port: {number: 8080}}
      - path: /
        pathType: Prefix
        backend:
          service: {name: frontend-svc, port: {number: 80}}
