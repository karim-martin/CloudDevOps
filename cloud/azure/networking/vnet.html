Azure VNet

Azure

Virtual Network — your isolated, secure network inside Azure.

VNet = Your Private Network in Azure

A VNet is Azure's equivalent of an on-prem network. It's isolated by default — nothing from the internet can reach it unless you explicitly open a path. You divide a VNet into subnets: a public subnet hosts load balancers that internet traffic reaches; a private subnet hosts your AKS nodes and databases. Network Security Groups (NSGs) are stateful firewalls applied to subnets or individual NICs.

VNet Design for AKS

VNet: 10.0.0.0/8  (large address space for pods!)
├── Public Subnet     10.1.0.0/16  ← Application Gateway, Azure Firewall
├── AKS Node Subnet   10.2.0.0/16  ← Worker nodes (Azure CNI)
├── Pod Subnet        10.3.0.0/16  ← Pod IPs (Azure CNI Overlay)
└── Private Subnet    10.4.0.0/16  ← Azure SQL, Azure Cache (private endpoints)

Create VNet with Terraform

resource "azurerm_virtual_network" "main" {
  name                = "myapp-vnet"
  location            = "eastus"
  resource_group_name = azurerm_resource_group.main.name
  address_space       = ["10.0.0.0/8"]
}

resource "azurerm_subnet" "aks_nodes" {
  name                 = "aks-nodes"
  resource_group_name  = azurerm_resource_group.main.name
  virtual_network_name = azurerm_virtual_network.main.name
  address_prefixes     = ["10.2.0.0/16"]
}

# Network Security Group — restrict database access
resource "azurerm_network_security_rule" "allow_aks_to_db" {
  name                        = "allow-aks-to-db"
  priority                    = 100
  direction                   = "Inbound"
  access                      = "Allow"
  protocol                    = "Tcp"
  source_address_prefix       = "10.2.0.0/16"  # AKS subnet
  destination_address_prefix  = "10.4.0.0/16"  # DB subnet
  destination_port_range      = "1433"          # SQL Server
  source_port_range           = "*"
  resource_group_name         = azurerm_resource_group.main.name
  network_security_group_name = azurerm_network_security_group.db.name
}

Private Endpoints

Private endpoints give Azure PaaS services (Azure SQL, Storage, Key Vault) a private IP inside your VNet. Traffic never leaves your VNet — no public internet exposure.

resource "azurerm_private_endpoint" "sql" {
  name                = "sql-private-endpoint"
  location            = "eastus"
  resource_group_name = azurerm_resource_group.main.name
  subnet_id           = azurerm_subnet.private.id

  private_service_connection {
    name                           = "sql-psc"
    private_connection_resource_id = azurerm_mssql_server.main.id
    subresource_names              = ["sqlServer"]
    is_manual_connection           = false
  }
}
