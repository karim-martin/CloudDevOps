GitOps & ArgoCD

Deploy by merging a PR — GitOps uses Git as the single source of truth for cluster state.

What is GitOps?

Traditional CI/CD: your pipeline pushes changes to the cluster ("push model"). GitOps flips this: a tool running inside the cluster watches a Git repo and pulls changes automatically ("pull model"). The Git repo becomes the exact truth about what should be running. To deploy, you just merge a PR — the cluster self-heals to match.

GitOps Flow with ArgoCD
👤 Developer
Merges PR → updates K8s manifests in Git
📁 Git Repo
Single source of truth for cluster state
🔄 ArgoCD
Watches Git repo, syncs cluster automatically
☸️ Kubernetes Cluster
State matches Git — always

Install ArgoCD

# Create namespace and install
kubectl create namespace argocd
kubectl apply -n argocd -f https://raw.githubusercontent.com/argoproj/argo-cd/stable/manifests/install.yaml

# Wait for pods to be ready
kubectl wait --for=condition=ready pod -l app.kubernetes.io/name=argocd-server -n argocd --timeout=120s

# Port-forward the ArgoCD UI
kubectl port-forward svc/argocd-server -n argocd 8080:443

# Get admin password
kubectl -n argocd get secret argocd-initial-admin-secret \
  -o jsonpath="{.data.password}" | base64 -d && echo

Connect ArgoCD CLI

# Install argocd CLI
brew install argocd  # macOS

# Log in
argocd login localhost:8080 --username admin --password <password> --insecure

# Change password
argocd account update-password

Create an ArgoCD Application

# myapp-argocd.yaml
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: myapp
  namespace: argocd
spec:
  project: default
  source:
    repoURL: https://github.com/myorg/myapp-k8s.git
    targetRevision: main
    path: manifests/           # folder with K8s YAML files
  destination:
    server: https://kubernetes.default.svc
    namespace: myapp
  syncPolicy:
    automated:
      prune: true              # delete removed resources
      selfHeal: true           # revert manual kubectl changes
    syncOptions:
    - CreateNamespace=true
kubectl apply -f myapp-argocd.yaml
argocd app get myapp
argocd app sync myapp

GitOps Repository Structure

myapp-k8s/
├── base/                  # Base Kubernetes manifests
│   ├── deployment.yaml
│   ├── service.yaml
│   └── kustomization.yaml
└── overlays/
    ├── staging/           # Staging-specific patches
    │   ├── replicas.yaml
    │   └── kustomization.yaml
    └── production/        # Production-specific patches
        ├── replicas.yaml
        └── kustomization.yaml
Push vs Pull — Key Difference

Push CI/CD (GitHub Actions, Azure Pipelines): The pipeline needs cluster credentials stored as secrets. If someone deletes a deployment manually, it stays deleted until the next deploy.
Pull GitOps (ArgoCD): No external credentials needed. If someone deletes a deployment, ArgoCD recreates it within 3 minutes. Drift is impossible.

StrategyBehaviorUse Case
ManualChanges only apply when you run argocd app syncProduction — require human approval
