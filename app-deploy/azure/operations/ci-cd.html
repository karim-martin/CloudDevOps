Azure Pipelines CI/CD

Build, test, and deploy automatically on every push — using OIDC workload federation (no stored credentials).

What Does This Pipeline Do?

Every time you push code to the main branch: (1) Azure Pipelines builds and tests your code, (2) builds Docker images and pushes to ACR, (3) deploys new images to AKS. The pipeline authenticates to Azure using a Federated Credential — no passwords or service principal secrets are stored.

azure-pipelines.yml

# azure-pipelines.yml
trigger:
  branches:
    include:
    - main

variables:
  ACR_NAME: myappacr
  AKS_CLUSTER: myapp-aks
  RESOURCE_GROUP: myapp-rg
  NAMESPACE: myapp

stages:
- stage: Build
  displayName: Build & Push Images
  jobs:
  - job: BuildImages
    pool:
      vmImage: ubuntu-latest
    steps:
    - task: AzureCLI@2
      displayName: Login to ACR
      inputs:
        azureSubscription: myapp-service-connection
        scriptType: bash
        scriptLocation: inlineScript
        inlineScript: |
          az acr login --name $(ACR_NAME)

    - script: |
        docker build -f Dockerfile.frontend \
          -t $(ACR_NAME).azurecr.io/frontend:$(Build.BuildId) \
          -t $(ACR_NAME).azurecr.io/frontend:latest ./frontend
        docker push $(ACR_NAME).azurecr.io/frontend:$(Build.BuildId)
        docker push $(ACR_NAME).azurecr.io/frontend:latest
      displayName: Build & Push Frontend

    - script: |
        docker build -f Dockerfile.backend \
          -t $(ACR_NAME).azurecr.io/backend:$(Build.BuildId) \
          -t $(ACR_NAME).azurecr.io/backend:latest ./backend
        docker push $(ACR_NAME).azurecr.io/backend:$(Build.BuildId)
        docker push $(ACR_NAME).azurecr.io/backend:latest
      displayName: Build & Push Backend

- stage: Deploy
  displayName: Deploy to AKS
  dependsOn: Build
  jobs:
  - deployment: DeployToAKS
    pool:
      vmImage: ubuntu-latest
    environment: production
    strategy:
      runOnce:
        deploy:
          steps:
          - task: AzureCLI@2
            displayName: Deploy to AKS
            inputs:
              azureSubscription: myapp-service-connection
              scriptType: bash
              scriptLocation: inlineScript
              inlineScript: |
                az aks get-credentials \
                  --resource-group $(RESOURCE_GROUP) \
                  --name $(AKS_CLUSTER)

                kubectl set image deployment/frontend \
                  frontend=$(ACR_NAME).azurecr.io/frontend:$(Build.BuildId) \
                  -n $(NAMESPACE)

                kubectl set image deployment/backend \
                  backend=$(ACR_NAME).azurecr.io/backend:$(Build.BuildId) \
                  -n $(NAMESPACE)

                kubectl rollout status deployment/frontend -n $(NAMESPACE)
                kubectl rollout status deployment/backend -n $(NAMESPACE)

Set Up Service Connection

In Azure DevOps, go to Project Settings → Service Connections → New → Azure Resource Manager. Choose Workload Identity Federation — Azure DevOps creates a federated credential automatically. No secrets stored.
