Scaling

Scale pods with HPA and nodes with Cluster Autoscaler — handle traffic spikes automatically.

Two Levels of Scaling

HPA (Horizontal Pod Autoscaler) adds more copies of your app pod when CPU usage is high. Cluster Autoscaler adds more VMs (nodes) to AKS when there's no room for new pods. Together they handle traffic spikes without manual intervention.

Horizontal Pod Autoscaler

# hpa.yaml
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: backend-hpa
  namespace: myapp
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: backend
  minReplicas: 2
  maxReplicas: 10
  metrics:
  - type: Resource
    resource:
      name: cpu
      target:
        type: Utilization
        averageUtilization: 70
  - type: Resource
    resource:
      name: memory
      target:
        type: Utilization
        averageUtilization: 80
kubectl apply -f hpa.yaml
kubectl get hpa -n myapp -w

Cluster Autoscaler

Cluster Autoscaler is automatically configured when you use enable_auto_scaling = true in the Terraform AKS node pool. Set min_count and max_count to define boundaries.

# Verify autoscaler is running
kubectl get pods -n kube-system | grep cluster-autoscaler

# View autoscaler logs
kubectl logs -n kube-system -l app=cluster-autoscaler --tail=50
KEDA for Event-Driven Scaling

For scaling based on Azure Service Bus queue depth, Azure Storage queues, or custom metrics, use KEDA (Kubernetes Event-Driven Autoscaling). KEDA is a CNCF project that scales pods to zero when there's no work.
