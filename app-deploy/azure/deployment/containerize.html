Containerize Your Apps

Multi-stage Dockerfiles for React and .NET 8 — small, secure production images.

What is a Multi-Stage Build?

A multi-stage Dockerfile uses one container to build the app (Node/SDK) and a second, smaller container to run it (Nginx/ASP.NET runtime). The final image doesn't include build tools — only the compiled output. This makes images 5–10× smaller and more secure.

React Frontend Dockerfile

# Dockerfile.frontend
FROM node:20-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci --only=production
COPY . .
RUN npm run build

FROM nginx:alpine AS runner
COPY --from=builder /app/dist /usr/share/nginx/html
COPY nginx.conf /etc/nginx/nginx.conf
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]

Nginx Config (React SPA)

# nginx.conf
events {}
http {
  include /etc/nginx/mime.types;
  server {
    listen 80;
    root /usr/share/nginx/html;
    index index.html;

    location / {
      try_files $uri $uri/ /index.html;
    }

    location /api/ {
      proxy_pass http://backend-service:8080/;
      proxy_set_header Host $host;
      proxy_set_header X-Real-IP $remote_addr;
    }
  }
}

.NET 8 Backend Dockerfile

# Dockerfile.backend
FROM mcr.microsoft.com/dotnet/sdk:8.0 AS builder
WORKDIR /app
COPY *.csproj ./
RUN dotnet restore
COPY . .
RUN dotnet publish -c Release -o /publish

FROM mcr.microsoft.com/dotnet/aspnet:8.0 AS runner
WORKDIR /app
COPY --from=builder /publish .
USER app
EXPOSE 8080
ENTRYPOINT ["dotnet", "MyApp.Api.dll"]

Build and Push to ACR

LOGIN_SERVER="myappacr.azurecr.io"
az acr login --name myappacr

# Build and push frontend
docker build -f Dockerfile.frontend -t $LOGIN_SERVER/frontend:latest ./frontend
docker push $LOGIN_SERVER/frontend:latest

# Build and push backend
docker build -f Dockerfile.backend -t $LOGIN_SERVER/backend:latest ./backend
docker push $LOGIN_SERVER/backend:latest
