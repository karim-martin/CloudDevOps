IRSA — IAM Roles for Service Accounts

AWS

Grant AWS permissions to EKS pods without any credentials.

IRSA = Your Pod Has an AWS Identity

IRSA links a Kubernetes Service Account to an IAM Role. When a pod uses that Service Account, it automatically gets temporary AWS credentials for the IAM Role — no hardcoded access keys, no secrets to rotate. AWS verifies the pod's identity via OIDC (a web standard for federated identity).

How IRSA Works

IRSA Authentication Flow
📦 Pod
Calls AWS SDK (e.g., read from S3)
🎫 AWS SDK finds projected token
/var/run/secrets/eks.amazonaws.com/serviceaccount/token
🔐 STS AssumeRoleWithWebIdentity
Exchanges OIDC token for temp credentials
✅ Temporary IAM Credentials
Valid 1hr, auto-rotated — no hardcoded keys!

Setup IRSA Step by Step

# 1. Associate OIDC provider with cluster (one-time)
eksctl utils associate-iam-oidc-provider \
  --cluster myapp-cluster \
  --approve

# 2. Create IAM policy for backend access
aws iam create-policy \
  --policy-name MyAppBackendPolicy \
  --policy-document file://iam-policy.json

# iam-policy.json:
# {
#   "Statement": [
#     {"Effect": "Allow", "Action": "secretsmanager:GetSecretValue",
#      "Resource": "arn:aws:secretsmanager:us-east-1:123:secret:myapp/*"},
#     {"Effect": "Allow", "Action": ["s3:GetObject", "s3:PutObject"],
#      "Resource": "arn:aws:s3:::myapp-uploads/*"}
#   ]
# }

# 3. Create service account with IAM role attached
eksctl create iamserviceaccount \
  --cluster myapp-cluster \
  --namespace production \
  --name backend-sa \
  --attach-policy-arn arn:aws:iam::123:policy/MyAppBackendPolicy \
  --approve

# 4. Reference the service account in your deployment
# spec.serviceAccountName: backend-sa
